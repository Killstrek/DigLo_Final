# โจทย์

**CEDT Final Project 2569 Digital Logic 2110252: Mini CPU + Stack**

## ภาพรวมโจทย์

ให้นิสิตสร้าง CPU ขนาด 8 bits ด้วยโปรแกรม Digital ขั้นแรกวงจรรอรับโปรแกรมมาเก็บใน
RAM ขนาด 256 x 14 bits (pRAM – Program RAM) แล้วทำตามคำสั่งตั้งแต่ address
0x00 ไปจนเจอคำสั่ง STOP จากนั้นรอสัญญาณให้ส่งคำตอบ แล้วแสดงผลลัพธ์ที่เก็บใน RAM ขนาด
256 x 8 bits (rRAM – Result RAM) ตำแหน่ง 0x00–0x0F ออกทาง output และ
7-segment 2 ตัว

CPU นี้มีองค์ประกอบหลักดังนี้

- register 8 bits: accA, accB (accumulator), regC, regD และ SP (Stack
  > Pointer)

- flag 3 ตัว: eq, gr, ls ใช้กับคำสั่ง jump

- stack อยู่ใน rRAM ช่วงบน ใช้ผ่านคำสั่ง PUSH / POP

- คำสั่งพื้นฐาน 42 คำสั่ง จัดกลุ่มตาม bit ของ opcode

- ช่วงท้ายโครงงานจะมีคำสั่งพิเศษ (Secret) ปล่อยเพิ่มในช่อง opcode ที่สงวนไว้
  > ควรออกแบบวงจรให้ต่อยอดได้

accumulator คือ register ที่เก็บค่าส่งเข้า ALU และรับผลลัพธ์กลับมา (อ่านเพิ่ม:
https://en.wikipedia.org/wiki/Accumulator\_(computing))

## จังหวะสัญญาณที่ testcase จะส่งมา

สัญญาณควบคุม reset, progLoad, start, result จะเป็น 1 ทีละตัวเสมอ ไม่มีสองตัวเป็น
1 พร้อมกัน และเปลี่ยนค่าตอน clk = 0 เพื่อให้ค่านิ่งก่อนขอบขาขึ้น

| สัญญาณ    | สิ่งที่ testcase รับประกัน                                                                                                  | สิ่งที่วงจรต้องทำ                                                                                                                                                                                  |
|----------|-----------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| reset    | มาได้ทุกเมื่อ รวมระหว่างรันโปรแกรมและก่อน done หลัง reset มี clock ว่างอย่างน้อย 20 clocks ก่อนสัญญาณถัดไป                           | หยุดทันที ล้างค่าตามหัวข้อค่าเริ่มต้น แล้วรอคำสั่งใหม่ ทำแบบ synchronous หรือ asynchronous ก็ได้                                                                                                                |
| progLoad | ก่อนโหลดโปรแกรมใหม่จะมี reset เสมอ progIn มีค่าถูกต้องก่อนขอบขาขึ้นทุกครั้ง                                                        | เก็บคำสั่งแรกที่ pRAM\[0x00\] ทุกครั้ง (เขียนทับของเดิม) ไม่ต่อจาก address ล่าสุด                                                                                                                            |
| start    | เป็น 1 เพียง 1 clock อาจมาต่อจาก progLoad ทันที, มาหลัง reset โดยไม่โหลดโปรแกรมใหม่ หรือมาหลัง done เพื่อรันโปรแกรมเดิมด้วย M, N ใหม่ | PC = 0x00 และ SP = 0x00 แล้วเริ่มทำงาน                                                                                                                                                           |
| M, N     | มีค่าระหว่างรันโปรแกรม ค้างนานพอให้คำสั่งที่อ่าน M, N ทำงานทัน ไม่มีค่าในช่วง progLoad                                                | อ่านค่าตอนทำคำสั่งเท่านั้น นอกนั้นไม่ต้องสนใจ                                                                                                                                                            |
| result   | เป็น 1 เพียง 1 clock และมาหลัง valid = 1 เสมอ ถ้าวงจรยังทำไม่เสร็จตอน result มาถึง นับว่าผิด ขอ result ซ้ำหลัง done ได้             | rRAM\[0x00\] ต้องออกที่ output ทันทีหลังขอบขาขึ้นของ clock ที่อ่าน result = 1 จากนั้นส่ง rRAM\[0x01\], rRAM\[0x02\], … ทุก 1 clock จนครบ 16 ค่า แล้วตั้ง done = 1 ที่ขอบขาขึ้นถัดไป นอกช่วงส่ง ค่า output เป็น don't care |

**จำนวน clock:** testcase เผื่อให้อย่างน้อย 4 clocks ต่อคำสั่งพื้นฐาน
ถ้าออกแบบให้แต่ละคำสั่งใช้ไม่เกิน 4 clocks จะทันทุก testcase ส่วนคำสั่งพิเศษที่วนลูปจะเผื่อ
clock เพิ่มตามที่ระบุใน Excel testcase ทุกโปรแกรมมี STOP เสมอ ไม่มีกรณีรันเลย 0xFF

## ข้อกำหนดการออกแบบ

- ใช้อุปกรณ์มาตรฐานใน Digital ได้ทุกชนิด แนะนำให้ใช้ tunnel เพื่อให้วงจรอ่านง่าย

- pRAM และ rRAM ต้องเป็น RAM ที่มี address port เดียว อย่างละ 1 ตัว ได้แก่ RAM,
  > separated Ports (แบบที่ใช้ใน template), RAM, bidirectional Port หรือ
  > RAM, Chip Select **ห้ามใช้ RAM, Dual Port** หรือแยกเก็บข้อมูลซ้ำใน register
  > ชุดอื่น (อาจารย์จะตรวจไฟล์ .dig ประกอบ)

- CPU ต้องเป็น Multiple Cycle CPU หรือ Pipeline ไม่อนุญาต Single Cycle CPU:
  > แต่ละคำสั่งต้องใช้อย่างน้อย 2 clocks โดย fetch แยกจาก execute ถ้า fetch
  > คำสั่งและเขียนผลเสร็จในขอบขาขึ้นเดียวกัน นับเป็น Single Cycle ไม่จำเป็นต้องทำ
  > pipeline

- control unit ทำเป็น sequential logic หรือ microprogram ก็ได้
  > แต่ละคำสั่งใช้จำนวน clock เท่ากันหรือไม่เท่ากันก็ได้

- ใช้ ROM ได้ เช่นทำ microprogram หรือ decoder ยกเว้นคำสั่งพิเศษ GCD และ FIB
  > ที่ต้องทำแบบวนลูปผ่าน ASM ห้ามใช้ ROM หรือ lookup table เก็บคำตอบ

- คำนวณแบบ 8 bits เป็นหลัก เลขคณิตศาสตร์เป็น 2’s complement
  > ยกเว้นที่ระบุเป็นอย่างอื่น ผลที่เกิน 8 bits ให้เก็บ 8 bits ล่าง ทิ้งส่วนเกิน

- ไม่จำเป็นต้องทำครบทุกคำสั่ง แต่ละ testcase จะใช้คำสั่งเพียงบางส่วน

- opcode ที่ระบุว่ายังไม่ใช้หรือสงวนไว้ จะไม่ปรากฏใน testcase ของคำสั่งพื้นฐาน

- ใช้ positive edge clock ในการ synchronous วงจร

### ค่าเริ่มต้นและการรันซ้ำ

| เหตุการณ์   | สิ่งที่ต้องเกิดขึ้น                                                                                                                              |
|-----------|------------------------------------------------------------------------------------------------------------------------------------------|
| reset = 1 | PC, SP, accA, accB, regC, regD, flag ทุกตัว = 0 และ rRAM\[0x00–0x0F\] = 0 ไม่ต้องล้าง pRAM (หลัง reset จึง start ต่อได้เลยโดยไม่ต้องโหลดโปรแกรมใหม่) |
| start = 1 | PC = 0x00 และ SP = 0x00 ส่วน register อื่น flag และ rRAM คงค่าเดิม (testcase จะไม่อาศัยค่าค้างของ register)                                       |
| หลัง done  | ไม่ต้อง reset อะไร รอ reset / progLoad / start / result รอบถัดไป                                                                            |

### 

### กติกาของ flag

- CMP ตั้ง flag ตามผลการเทียบ ตัวเดียวเป็น 1 อีกสองตัวเป็น 0 เสมอ

- isPrime แก้เฉพาะ eq (เป็นจำนวนเฉพาะ → 1, ไม่ใช่ → 0) ไม่แตะ gr และ ls เช่น
  > (gr, eq, ls) = (1, 0, 0) แล้ว isPrime เป็นจริง จะได้ (1, 1, 0)

- คำสั่ง jump ใช้ flag จาก CMP หรือ isPrime ครั้งล่าสุด ไม่จำเป็นต้องอยู่ติดกัน

- flag ถูกล้างเฉพาะตอน reset ไม่ถูกล้างตอน start

- คำสั่งอื่นที่ไม่ได้พูดถึง flag จะไม่เปลี่ยนค่า flag

### 

### กติกาของ Stack

- stack อยู่ใน rRAM โตลงจาก 0xFF ลงมา (full descending)

- SP ขนาด 8 bits ชี้ไปที่ข้อมูลบนสุดของ stack ค่า 0x00 หมายถึง stack ว่าง

- PUSH x: SP ← SP − 1 แล้ว rRAM\[SP\] ← x (ค่าแรกที่ push จะอยู่ที่ 0xFF)

- POP x: x ← rRAM\[SP\] แล้ว SP ← SP + 1

- testcase จะไม่ POP ตอน stack ว่าง และจะไม่ PUSH ลึกเกิน 32 ชั้น (ไม่ต้องจัดการ
  > overflow / underflow)

- พื้นที่ stack (0xE0–0xFF) ไม่ทับช่วงแสดงผล 0x00–0x0F

## รูปแบบคำสั่งและ Opcode

คำสั่งขนาด 14 bits แบ่งเป็น opcode 6 bits \[13:8\] และ operand 8 bits
\[7:0\] มีคำสั่งพื้นฐาน 42 คำสั่ง จัดกลุ่มตาม bit ของ opcode ดังนี้

- opcode\[5:4\] = กลุ่มคำสั่ง (00 Data, 01 Memory/Stack, 10 ALU, 11
  > Control/Special)

- opcode\[3:2\] = ชุดคำสั่งย่อยภายในกลุ่ม ชุดละ 4 ช่อง

- opcode\[1:0\] = คำสั่งในชุด ช่องที่เขียนว่า “ยังไม่ใช้” หรือ “สงวนไว้” จะไม่ปรากฏใน
  > testcase ของคำสั่งพื้นฐาน

| กลุ่ม \[5:4\]     | ชุด \[3:2\] | ชื่อชุด                 | จำนวนคำสั่ง |
|-----------------|------------|----------------------|-----------|
| 00 Data         | 00         | Immediate            | 3         |
| 00 Data         | 01         | คัดลอกจาก accA / accB | 4         |
| 00 Data         | 10         | คัดลอกเข้า accA        | 3         |
| 00 Data         | 11         | อ่าน Input            | 2         |
| 01 Memory/Stack | 00         | Direct memory        | 3         |
| 01 Memory/Stack | 01         | Indirect memory      | 2         |
| 01 Memory/Stack | 10         | Stack                | 2         |
| 01 Memory/Stack | 11         | (สงวนไว้)             | 0         |
| 10 ALU          | 00         | Arithmetic           | 3         |
| 10 ALU          | 01         | Division             | 2         |
| 10 ALU          | 10         | Logic                | 4         |
| 10 ALU          | 11         | Shift / Rotate       | 4         |
| 11 Control      | 00         | Branch               | 4         |
| 11 Control      | 01         | Loop                 | 1         |
| 11 Control      | 10         | Compare / Test       | 2         |
| 11 Control      | 11         | คำสั่งพิเศษ + STOP      | 3         |

### 10xxxx — ALU (ผลลัพธ์เก็บที่ accA)

| Opcode  | ชุด         | คำสั่ง                    | ความหมาย                                  |
|---------|------------|-------------------------|-------------------------------------------|
| 10 0000 | Arithmetic | accA ← accA + accB      | 2’s complement ไม่สนใจ overflow            |
| 10 0001 | Arithmetic | accA ← accA − accB      | 2’s complement ไม่สนใจ overflow            |
| 10 0010 | Arithmetic | accA ← accA × accB      | accA\[3:0\] × accB\[3:0\] แบบไม่มีเครื่องหมาย |
| 10 0011 | Arithmetic | —                       | ยังไม่ใช้                                    |
| 10 0100 | Division   | accA ← accA / accB      | แบบไม่มีเครื่องหมาย (testcase ไม่หารด้วย 0)     |
| 10 0101 | Division   | accA ← accA % accB      | แบบไม่มีเครื่องหมาย (testcase ไม่ mod ด้วย 0)   |
| 10 0110 | Division   | —                       | ยังไม่ใช้                                    |
| 10 0111 | Division   | —                       | ยังไม่ใช้                                    |
| 10 1000 | Logic      | accA ← accA AND accB    | bitwise                                   |
| 10 1001 | Logic      | accA ← accA OR accB     | bitwise                                   |
| 10 1010 | Logic      | accA ← accA XOR accB    | bitwise                                   |
| 10 1011 | Logic      | accA ← NOT accA         | กลับบิต accA                                |
| 10 1100 | Shift      | accA ← accA \<\< accB   | logical shift left                        |
| 10 1101 | Shift      | accA ← accA \>\> accB   | logical shift right                       |
| 10 1110 | Shift      | accA ← accA \<\<\< accB | rotate left                               |
| 10 1111 | Shift      | accA ← accA \>\>\> accB | rotate right                              |

ชุด Shift: จำนวนครั้งที่เลื่อนคือ accB\[2:0\] แบบไม่มีเครื่องหมาย (0–7) bit\[0\] ของ
opcode = ทิศ (0 ซ้าย, 1 ขวา) และ bit\[1\] = ชนิด (0 shift, 1 rotate)

## ตัวอย่างการทำงาน

โปรแกรมนี้สลับค่า M กับ N ผ่าน stack และบันทึกค่า SP ขณะมีข้อมูล 2 ชั้น กำหนดให้ M =
0x12 และ N = 0x34

| pRAM | Instruction (14 bits) | คำสั่ง                | ผล                             |
|------|-----------------------|---------------------|--------------------------------|
| 0x00 | 00 1100 0000 0000     | regC ← M            | regC = 0x12                    |
| 0x01 | 00 1101 0000 0000     | regD ← N            | regD = 0x34                    |
| 0x02 | 00 1000 0000 0000     | accA ← regC         | accA = 0x12                    |
| 0x03 | 01 1000 0000 0000     | PUSH accA           | SP = 0xFF, rRAM\[0xFF\] = 0x12 |
| 0x04 | 00 1001 0000 0000     | accA ← regD         | accA = 0x34                    |
| 0x05 | 01 1000 0000 0000     | PUSH accA           | SP = 0xFE, rRAM\[0xFE\] = 0x34 |
| 0x06 | 00 1010 0000 0000     | accA ← SP           | accA = 0xFE                    |
| 0x07 | 01 0001 0000 0010     | rRAM\[0x02\] ← accA | rRAM\[0x02\] = 0xFE            |
| 0x08 | 01 1001 0000 0000     | POP accA            | accA = 0x34, SP = 0xFF         |
| 0x09 | 01 0001 0000 0000     | rRAM\[0x00\] ← accA | rRAM\[0x00\] = 0x34            |
| 0x0A | 01 1001 0000 0000     | POP accA            | accA = 0x12, SP = 0x00         |
| 0x0B | 01 0001 0000 0001     | rRAM\[0x01\] ← accA | rRAM\[0x01\] = 0x12            |
| 0x0C | 11 1111 0000 0000     | STOP                | valid = 1                      |

ลำดับสัญญาณ:

1.  reset = 1 แล้วมี clock อย่างน้อย 20 clocks วงจรตั้งค่าเริ่มต้นและเคลียร์
    > rRAM\[0x00–0x0F\]

2.  progLoad = 1 แล้วส่งคำสั่ง 13 คำสั่งทาง progIn เก็บที่ pRAM\[0x00–0x0C\] จน
    > progLoad = 0

3.  start = 1 (1 clock) วงจรทำงานตามตารางด้านบนจนถึง STOP แล้วตั้ง valid = 1

4.  result = 1 (1 clock) หลังขอบขาขึ้นนั้น output = rRAM\[0x00\] = 0x34
    > แล้วตามด้วย 0x12, 0xFE, 0x00, …, 0x00 ทีละ clock

5.  ส่งครบ 16 ค่าแล้วตั้ง done = 1 และต้องรับ reset, progLoad, start, result
    > รอบถัดไปได้ต่อเนื่อง

## การทำงานในทีม

- ทำงานกลุ่มละ 3–4 คน จับกลุ่มกันเอง กลุ่ม 2 คนอนุโลมได้
  > แต่ถ้ามีเพื่อนไม่มีกลุ่มอาจขอให้รับเพิ่ม

- ปรึกษากันระหว่างกลุ่มและศึกษาตัวอย่างจากแหล่งต่างๆ ได้ แต่ห้ามคัดลอกไฟล์วงจรของกลุ่มอื่น

- ใช้ generative AI ช่วยวิเคราะห์และพัฒนาวงจรได้
  > แต่ทุกคนในกลุ่มต้องอธิบายวงจรของกลุ่มได้

- ใส่ชื่อกลุ่ม รหัส ชื่อ และหน้าที่ของสมาชิกทุกคนไว้ในไฟล์ .dig (ใส่กรอบและ label
  > ในวงจร)
